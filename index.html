// methodology
01 Cohort construction — SQL window function
Users grouped by first transaction month using DATE_TRUNC and MIN(txn_date). FIRST_VALUE window function partitioned by cohort_month calculates retention % at each subsequent month. Active = at least one transaction in the 30-day window.
-- Retention % at each cohort month
SELECT cohort_month, activity_month,
  COUNT(DISTINCT user_id) AS retained,
  ROUND(COUNT(DISTINCT user_id) * 100.0 /
    FIRST_VALUE(COUNT(DISTINCT user_id))
    OVER (PARTITION BY cohort_month ORDER BY activity_month), 1
  ) AS retention_pct
FROM (
  SELECT user_id,
    DATE_TRUNC('month', MIN(txn_date)) AS cohort_month,
    DATE_TRUNC('month', txn_date) AS activity_month
  FROM transactions
  GROUP BY user_id, DATE_TRUNC('month', txn_date)
) t
GROUP BY cohort_month, activity_month
ORDER BY cohort_month, activity_month;
02 LTV segmentation — revenue bucketing
Segments defined by 12-month cumulative revenue: Premium £200+, Standard £50–£199, Freemium below £50. Churn rate per segment = average of (users lost in month N / users active in month N−1) across the 18-month observation window.
03 Churn-adjusted forecast — £ quantification
Forecast assumes current ARPU held constant with zero incremental churn from the observation baseline. Gap = revenue destroyed by churn each month. Converts churn from an operational % into a direct £ business cost.
04 Month-3 drop & activation split
Month-3 drop identified by averaging month-on-month delta across all four cohorts — consistent across cohorts, confirming structural onboarding friction rather than cohort-specific noise. Activation split: Premium cohort divided at day-30 by feature count (1 vs 3+), survival rates compared at month 6.
